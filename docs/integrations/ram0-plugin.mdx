The full automation plugin gives Codex, Claude Code, Cursor, and OpenCode Ram0's six MCP tools, lifecycle retrieval, bounded durable capture, and 12 workflow skills. Do not register both direct MCP and the full plugin in one client.

## Install

Install from the generated remote marketplace; no Ram0 source checkout is required.

```bash
# Claude Code
claude plugin marketplace add https://github.com/olhapi/ram0-plugins.git
claude plugin install ram0@ram0-plugins

# Codex
codex plugin marketplace add https://github.com/olhapi/ram0-plugins.git
codex plugin add ram0@ram0-plugins
```

Restart the client. In Codex, open `/hooks`, review the lifecycle hooks, and trust them; approve the hooks when Claude Code prompts. The trusted startup hook installs the bundled CLI atomically, while MCP starts directly from the plugin bundle.

Create an API key on the dashboard; it is shown once. Then run:

```bash
ram0 setup --url 'https://ram0.example.lan'
ram0 config test
```

The hidden prompt stores exactly the URL and key in `~/.config/ram0/config.json` (`0700` directory, `0600` file). Install and update preserve that config. The key is sent only as `Authorization: Bearer` to the configured endpoint; never paste it into MCP JSON, source control, prompts, plugin manifests, or dashboard fields.

For deliberate development/CI processes, non-empty `RAM0_API_URL` and `RAM0_API_KEY` override their individual stored fields. Normal setup requires no environment persistence.

## Update

```bash
# Codex
codex plugin marketplace upgrade ram0-plugins

# Claude Code
claude plugin marketplace update ram0-plugins
claude plugin update ram0@ram0-plugins
```

Restart after upgrading. Native updates preserve `~/.config/ram0/config.json`; they require no checkout, cache deletion, or plugin removal.

## Verify

Run `ram0 config test`, confirm the `ram0` MCP starts without an environment-variable warning, and invoke `health`. Call `remember`, start another task, then use `search_memories` to verify cross-task recall.

## Workflow skills

- Write: `remember`
- Browse: `peek`, `tour`
- Delete: `forget` (confirmation required)
- Portable data: `export`, `import` (bounded scan and reviewed batch)
- Quality: `memory-reviewer` (read-only), `dream` (confirmed consolidation), `stats`
- Setup: `health`, `onboard`
- Policy: `ram0-memory`

Plugin installation includes all skills automatically. OpenCode discovers all 12 bundled skills from the installed plugin. The `npx skills add ... --skill ram0-memory` command installs only the standalone policy skill.

## Direct MCP or skills-only

```bash
codex mcp add ram0 -- python3 ~/.local/share/ram0/mcp_stdio_adapter.py
claude mcp add ram0 --scope user -- python3 ~/.local/share/ram0/mcp_stdio_adapter.py
npx skills add https://github.com/olhapi/ram0 --skill ram0-memory
```

The plugin never sends or saves raw prompts, transcripts, file dumps, complete code/diffs, credentials, or identities. Missing configuration or an unavailable endpoint fails open. The server derives ownership from the API-key owner and rejects caller-selected identity fields.

## Migration

When an existing `ram0-plugins` marketplace points at a local checkout, replace that registration once. This is a local marketplace migration only; use native update commands afterward. Configuration is preserved.

```bash
# Codex
codex plugin remove ram0@ram0-plugins
codex plugin marketplace remove ram0-plugins
codex plugin marketplace add https://github.com/olhapi/ram0-plugins.git
codex plugin add ram0@ram0-plugins

# Claude Code
claude plugin uninstall ram0@ram0-plugins
claude plugin marketplace remove ram0-plugins
claude plugin marketplace add https://github.com/olhapi/ram0-plugins.git
claude plugin install ram0@ram0-plugins
```

Remove any duplicate direct Ram0 MCP entry before enabling the full plugin.

## Troubleshooting

- Rotate with `ram0 config set-key`.
- Repair permissions with `chmod 600 ~/.config/ram0/config.json`.
- Missing config: rerun `ram0 setup`. Unreachable endpoint: check `ram0 config show`, then `ram0 config test`.

## Development

Checkout installation is for contributors, not normal users:

```bash
git clone https://github.com/olhapi/ram0.git ~/ram0-development/ram0
python3 ~/ram0-development/ram0/integrations/ram0-plugin/scripts/install_cli.py
```

Cursor and OpenCode development installation remains checkout-based. The upstream `integrations/mem0-plugin` source is intentionally unchanged; see [UPSTREAM.md](https://github.com/olhapi/ram0/blob/main/integrations/ram0-plugin/UPSTREAM.md).
