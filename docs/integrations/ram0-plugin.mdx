title: "Ram0 Agent Plugin"
description: "Install persistent, account-scoped Ram0 automation in supported coding agents."
---

The full automation plugin gives Codex, Claude Code, Cursor, and OpenCode Ram0's six MCP tools plus lifecycle retrieval and bounded durable capture. Direct MCP is tools-only; skills-only is guidance. Do not register both direct MCP and the full plugin in one client.

## Permanent setup

Create an API key on the dashboard; it is shown once. Review the checkout, then run:

```bash
git clone https://github.com/olhapi/ram0.git ~/ram0-plugins/ram0
python3 ~/ram0-plugins/ram0/integrations/ram0-plugin/scripts/install_cli.py
ram0 setup --url 'https://ram0.example.lan'
ram0 config test
```

The hidden prompt stores exactly the URL and key in `~/.config/ram0/config.json` (`0700` directory, `0600` file). The key is sent only as `Authorization: Bearer` to the configured self-hosted endpoint. It is never stored as memory or logged and never sent to telemetry or third parties. Do not paste it into MCP JSON, source control, prompts, plugin manifests, or dashboard fields.

For deliberate development/CI processes, non-empty `RAM0_API_URL` and `RAM0_API_KEY` override their individual stored fields. Normal setup requires no environment persistence.

## Install full automation

```bash
# Claude Code
claude plugin marketplace add https://github.com/olhapi/ram0.git
claude plugin install ram0@ram0-plugins

# Codex
codex plugin marketplace add ~/ram0-plugins/ram0
codex plugin add ram0@ram0-plugins
```

Restart the client. In Codex, open `/hooks`, review the lifecycle hooks, and trust them. Cursor users select `~/ram0-plugins/ram0/.cursor-plugin/marketplace.json` under **Settings → Plugins → Add Marketplace**, install Ram0, and reload.

OpenCode uses the reviewed local package:

```bash
cd ~/ram0-plugins/ram0/integrations/ram0-plugin/.opencode-plugin
bun install --frozen-lockfile && bun run build
opencode plugin "file://$PWD" --global
```

## Direct MCP or skills-only

Direct MCP uses the installed transport without putting the key in client configuration:

```bash
codex mcp add ram0 -- python3 ~/.local/share/ram0/mcp_stdio_adapter.py
claude mcp add ram0 --scope user -- python3 ~/.local/share/ram0/mcp_stdio_adapter.py
```

Cursor and OpenCode use the same `python3` command and adapter path in local stdio MCP configuration. Skills-only searches before writing and installs concise guidance:

```bash
npx skills add https://github.com/olhapi/ram0 --skill ram0-memory
```

## Privacy and ownership

The plugin never sends or saves raw prompts, raw transcripts, file dumps, complete source/code/diff content, credentials, or identities. It captures only constrained durable decisions, preferences, conventions, architecture facts, verified facts, troubleshooting results, and follow-ups. Missing configuration or an unavailable endpoint fails open.

The server derives ownership from the API-key owner. Categories are private to that owner; first access copies the legacy template and onboarding appends missing definitions without replacing concurrent edits. Caller-selected `user_id`, agent, run, expiration, or credential fields are rejected.

## Migration and troubleshooting

- Remove the old `mem0-plugins` marketplace and duplicate remote Ram0 MCP entries; install `ram0@ram0-plugins`.
- Rotate with `ram0 config set-key`.
- Repair permissions with `chmod 600 ~/.config/ram0/config.json`.
- Missing config: rerun `ram0 setup`. Unreachable endpoint: check `ram0 config show`, then `ram0 config test`.

The upstream `integrations/mem0-plugin` source is intentionally unchanged; see [UPSTREAM.md](https://github.com/olhapi/ram0/blob/main/integrations/ram0-plugin/UPSTREAM.md).
