Ram0 serves a Bearer-authenticated Streamable HTTP endpoint at `/mcp`. It exposes six account-scoped tools and is separate from the hosted Mem0 Platform MCP.

## Choose a connection

Direct MCP is tools-only. The [full automation plugin](/integrations/ram0-plugin) registers the same tools and adds lifecycle retrieval and bounded durable capture. Skills-only adds search-before-write guidance. Do not register direct MCP and the full plugin together.

## Permanent setup

Create an API key on the dashboard; it is shown once. Review and install the local CLI:

```bash
git clone https://github.com/olhapi/ram0.git ~/ram0-plugins/ram0
python3 ~/ram0-plugins/ram0/integrations/ram0-plugin/scripts/install_cli.py
ram0 setup --url 'https://ram0.example.lan'
ram0 config test
```

`ram0 setup` reads the key without echo and stores it with the URL at `~/.config/ram0/config.json` (`0700` directory, `0600` file). The stable stdio bridge reads that protected file:

```bash
codex mcp add ram0 -- python3 ~/.local/share/ram0/mcp_stdio_adapter.py
claude mcp add ram0 --scope user -- python3 ~/.local/share/ram0/mcp_stdio_adapter.py
```

Cursor and OpenCode use the same `python3` command and adapter path in local stdio MCP JSON. The bridge sends the key only as `Authorization: Bearer` to the configured endpoint. It is never stored as memory or logged and never sent to telemetry or third parties. Ram0 does not accept `X-API-Key`, OAuth, browser sign-in, or caller-selected ownership at `/mcp`.

Non-empty `RAM0_API_URL` and `RAM0_API_KEY` can override individual stored fields for explicit development/CI processes; normal setup does not require exports.

## Available tools

| Tool | Purpose |
| --- | --- |
| `remember` | Store one user-authored memory. |
| `search_memories` | Search with a natural-language query. |
| `list_memories` | List the account's memories. |
| `get_memory` | Read an account-owned memory by UUID. |
| `update_memory` | Update an account-owned memory by UUID. |
| `forget_memory` | Delete an account-owned memory by UUID. |

The API-key owner determines the account-wide namespace; clients cannot choose another owner, agent, run, or expiration scope. MCP becomes available after ownership migration version 1 is ready.

## Verify and troubleshoot

Call `remember`, start a new task, then use `search_memories` to verify cross-task recall.

- Remove the old `mem0-plugins` marketplace or duplicate remote MCP before installing `ram0@ram0-plugins`.
- Rotate a key with `ram0 config set-key`.
- Repair permissions with `chmod 600 ~/.config/ram0/config.json`.
- Missing config: rerun `ram0 setup`. Unreachable endpoint: check `ram0 config show`, then `ram0 config test`.

The full plugin never sends or saves raw prompts, raw transcripts, file dumps, complete code/diffs, credentials, or identities. Categories are private to the API-key owner; first access copies the legacy template without overwriting later edits. The upstream `integrations/mem0-plugin` directory remains unchanged.
